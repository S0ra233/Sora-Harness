# Desktop 的翻译阅读页

本页仅说明当前 Desktop 的辅助显示，其他宿主无需加载。通用流程仍来自同一 Skill；上下文、检索和协作分别见[上下文组织](context.md)、[资料检索](retrieval.md)、[子 Agent 协作](collaboration.md)，工具名称映射见[宿主适配](hosts.md)。

## 打开与执行分开

- 插件分类的 `/翻译`／`/translation` 只打开只读对照页，不发送新的翻译请求。
- 技能分类的 `game-translation` 把 Skill 标记放进主输入框；用户发送后，宿主保存本次正文快照。模型也可通过实际开放的 `load_skill` 按需加载。已经随用户输入加载过正文时，不为同一任务再加载一遍。
- 正常问题、改译要求和结果说明仍在主聊天。页面按实际 Scene 与 Task 顺序显示原文和已保存译文，不使用模型回答中的一段文字冒充已提交译文。

有 `translation_projects` 时，只在本轮工作区内有界查找，由主 Agent 结合用户当前游戏和真实项目事实判断；多个候选不随意选择。`scan_complete=false`、深度限制、候选错误或拒绝访问都应保留。已知工作目录直接调用 `show_translation(work_dir=工作区内相对目录)`，成功返回查看引用；已创建的页面跟随新选择，未创建时提供“查看翻译”入口。

项目有效性由 Core 校验 `project.json`、`entries.json`、`tasks.jsonl` 的版本和一致性决定。有效项目的译文可以全部为空；只有游戏目录、零散 entry 文件或自制 JSON 不代表已建立翻译工作项目。页面尚未显示不等于 prepare/apply 失败，先检查真实执行结果与项目绑定。

手动选定的有效项目、Agent选定项目和当前Scene按对话保存在本地阅读记录中；有对话ID时重开可恢复绑定并读取最新文件。普通聊天导航不抢走独立窗口，从另一条对话明确打开时才恢复该对话的项目。目录失效应重新选择，不为修复页面重复prepare或apply；查看入口本身也不是翻译提交。

通过已开放的命令入口运行 Core，实际应用动作仍是 `package → 翻译结果文件 → apply`。成功的修改通知和重新打开页面沿原路线重读。主 Agent 审核子结果后提交即可；不要为了刷新直接改项目状态，也不要把 `show_translation` 当成提交入口。
