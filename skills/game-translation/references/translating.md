# 翻译与主 Agent 审核

先确认本轮目标语言、游戏语境和用户要处理的范围。已有翻译包中的 `localization`、`glossary.confirmed`、`glossary.pending`、`style` 和 `instructions` 与当前用户要求一起作为依据；若彼此实质冲突，指出具体字段并询问，不自行重写项目配置。没有资料不补设定，不把自己的译名意见标成用户已确认。

上下文范围与长场景处理见[上下文组织](context.md)，资料补充见[资料检索](retrieval.md)。不需要为了普通对白加载全部引擎说明；能从当前包确定的含义不重复检索。子任务返回结果也遵循本页规则，由主 Agent 核对完整目标集合后提交，具体分工见[协作说明](collaboration.md)。

## 读取一个包

- `target_ids` 是本次允许提交的完整目标集合。只为它们返回译文，不把 Scene 中的其他上下文也提交。
- `scene_context` 的非目标内容只读。`neighbors` 模式的前后文分别位于 `context_before`／`context_after`，不漏读，也不复制成结果项。
- `scene.kind` 与 `structure` 用于理解事件、选项、数据库或文本组；`scene.source_context` 提供实际文件／对象／字段来源。它们不证明每个相邻项都属于连续剧情。
- `speaker` 是已提取的说话人信息；不能因页面把它显示为 `说话人[文本]`，就在 `translation` 中再加一遍人物名。只有原目标文本本来包含的内容才进入译文。

## 输出与校验

保留原意、人物称谓和段落作用，遵守用户要求及实际 style，不默认改成摘要、扩写或固定文学腔。对选项、界面、名称和描述分别按用途翻译。`key`、资源路径、字段名和控制数据不是因为可读就需要翻译；候选范围按候选审查结果确定。

`{pN}` 是受保护标记，保持身份、次数和控制顺序。其他游戏占位符和自定义标签也可能影响运行；Core 通用检查不能证明它理解所有语法。遇到不明控制前缀先查看格式或使用处，不直接删掉。输出合法 UTF-8 JSON 数组，每项严格为：

```json
{"id":"包中的目标ID","translation":"{p0}实际译文{p1}","uncertain":false}
```

不为追求形式上的通过而编造缺项。无法确认语义、专名或缺失语境时保留问题并设 `uncertain=true`；能从已有材料自行核实的普通问题不必频繁打断用户。有 `request_user_input` 时沿宿主真实提问规则使用，不自建另一套等待或自动确认机制。

提交前核对返回项与目标 ID 的对应关系、重复或非目标 ID、保护标记、明显漏译和已确认术语。结果先写独立文件，再由 `apply` 验证和更新；不是把模型的自检结论直接写成 PROCESSED。缺项目标会成为 ERROR；保护标记、术语或 uncertain 可能成为 NEEDS_HUMAN。根据报告修正并重新导包，不改包版本／哈希，也不重试相同失败提交来碰运气。

报告实际处理范围、提交后的状态和仍待确认的问题。Core 接受、文本读回通过、翻译质量和游戏实机效果分别成立，不互相替代。
