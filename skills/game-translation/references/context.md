# 按任务组织翻译上下文

本页约束提供给翻译任务的资料，不修改宿主的聊天历史、压缩或缓存策略，也不改变 Core 的包格式。

## 开始与续作

先明确 WORK、目标语言和本次范围，复用已经确认的运行入口。已有项目先取 status 与实际包；从包和已保存文件恢复进度，不依据聊天中的“已完成”跳过真实状态检查。新聊天或压缩后继续时，保留 WORK、当前包 ID／路径、结果路径、已提交范围和未决问题即可定位；需要的译文与证据仍从原文件读取。

读取项目 glossary.md、proper_nouns.md 和 style.md 时，区分已确认术语、候选与风格。术语或风格发生实质变化后重新导出包，不能把新规则与旧包内容混成一个提交版本。

## 一次翻译需要什么

- 当前包的 id、project_id、target_ids、目标原文与受保护标记。
- 目标语言，以及包中的 instructions、localization、glossary 和 style；用户本次补充的范围和要求单独说明。
- 对应 scene.kind、structure、speaker 和 source_context。来源位置是证据，不等于用途或剧情顺序已经确认。
- 当前包所提供的必要上下文，以及真正相关的检索片段与来源；不要重复附上整份游戏资料或全部主聊天。

包是提交版本的依据，不就地裁剪、改 id 或改哈希。可以给子任务共享文件的准确路径，让它按目标读取；无法访问共享文件时提供本次所需的包与资料。不要把有限读取工具截断后的文本当成完整包。

## 根据场景选择大小

默认 scene 模式保留完整 Scene 的有序文本，不因选项、数据库或事件邻接就当作连续对白。同一 Scene 多条翻译可以共用一次上下文理解，逐条结果仍按 Task ID 对应。

Core 的 `package WORK --target TASK_ID --context neighbors --window 2` 只支持一个目标；前后文位于 context_before／context_after，不能漏读。语义不清时增加实际窗口或改用完整 Scene，不靠自行补剧情解决。

`--target` 可重复以选择同一 Scene 的多个目标，但 scene 模式仍包含完整 Scene 上下文，不会因此变成批量滑动窗口。默认包上限为60000字符，不是 token；超限会报错，不会自动截断。长 Scene 可沿已有单条邻近模式处理，或在确有上下文容量时明确提高 --max-chars。不要谎称已经有自动批量切片功能。

单纯把同一巨大 Scene 拆成许多目标包仍可能重复传输全文；先选择符合任务的现有模式，不以提高缓存命中代替控制总输入与请求次数。Skill 本身不承诺宿主或提供商的缓存效果。
